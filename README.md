# dsh-redo-live

> 编辑已经发出去的用户消息并原地重答——**回答还在生成时也能改**。

这是 [dsh-redo](https://github.com/Imzl-zl/dsh-redo) 的分支版本（fork），由 [@Imzl-zl](https://github.com/Imzl-zl) 创作上游。上游把「改完再发」做得很扎实：只追加日志、surface 原地替换、图片随行走、破坏性操作有确认。本分支只改一件事——**它不再要求你先停掉正在生成的回答**。

## 和上游的唯一区别

上游把「生成中禁用」当成特性：回答还在流的时候，编辑和重新生成按钮是灰的，你得先自己点停止。

这个分支把这一步自动化了：

```js
// 点击编辑时，如果这一轮还在跑：
await session.cancel()            // 官方停止入口（不是 hack）
// 每 100ms 轮询，直到会话真正空闲（最多等 8 秒）
// 然后照上游原来的流程：/relive <seq> → 原文回到输入框 → 你改 → 发送
```

带来的手感就是 Codex / ChatGPT 那种：看到答得不对，**直接在你还亮着的那条消息上点铅笔**，它替你停、替你回填，你改完按发送，对话就从那条重写。

上游那样的取舍自有道理（编辑器不主动打断模型工作），所以这里不是给上游提 patch，而是单独发一个包：想要自动停的人装这个，想要保守行为的人继续用上游。两者可以同时安装，互不干扰（命令、模块 id、RPC 前缀都不同）。

## 功能（继承自上游）

- **编辑重发**：消息连同它之后的回答从对话里消失，文字和图片回到输入框；改完发送，新内容落在原位。
- **重新生成**：任意一条用户消息原样重发，一键，不经过输入框。
- **图片跟着走**：存图读回字节、重新挂成草稿，发送时一起上送。
- **破坏性操作有确认**：撤回中段消息前告诉你之后有几轮离开上下文；输入框已有内容时再问一次是否替换。
- **版本化 surface**：改写以追加式 surface replace 实现，不改写原始日志。

## 命令

```
/relive <消息序号>     # 武装：下一条发出的消息替换掉那一条及其之后
/relive off           # 取消武装
```

（上游用 `/redo`，这里换成 `/relive` 以便两个插件同时安装。）

## 安装

```sh
dsh plugin add dsh-redo-live
```

或在插件市场 / Discover 里搜 `dsh-redo-live`。装完**重启 DSH**（客户端模块需要重新加载）。

要求 DSH `>= 0.2.2-alpha.2 < 0.3.0`。发布物已含构建好的 `lib/`，不需要自己 build。

## 兼容性说明

上游声明 `>=0.2.2-rc.1`，理由是「第一个带完整 `ImageAttachmentRef` 读取 API 的版本」。实测 `0.2.2-alpha.2` 的 `Session.readAttachment(attachment: ImageAttachmentRef)` 签名与 rc.1 **完全一致**，`@deepseek-ai/dsh-session` 两版逐字节相同，所以这里把下界放到 `0.2.2-alpha.2`。

## 已知边界

- 只处理纯文本与图片；带其它文件附件的消息不能编辑或重试（上游同）。
- 会话第一条消息不能改写（protected session head）。
- 停止失败或超时会给出错误提示，不会静默改写。
